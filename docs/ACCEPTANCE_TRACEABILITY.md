## 配置与证据判定

`config/acceptance/m1-v1.json` 使用 `polar.acceptance.v1`，status=draft。固定历史基线、自有组件身份与 80/150 ms 约束；5 s、六车场景、一激活视角、loopback 和 15 总 FPS 为当前开发预设，不是全场性能验收。RTF ≥0.95、操作手 ≥25 FPS、输入 P95 ≤100 ms、显示 P95 ≤150 ms 仍是候选目标，不是已承诺或已通过阈值。

运行 `python tools/validate_acceptance.py` 只验证配置；`--require-frozen` 用来拒绝未冻结配置。报告中的开发主机信息不自动指定验收目标机，`milestone_accepted=false` 不得改写为已通过。预设的 A01–A14 均 not_run；这表示本预设尚未执行验收，不抹掉计划中历史 live/OFFLINE24 失败记录。A15 保留单独硬件授权状态。

每份测试报告至少关联：A/T/R 编号、配置哈希、提交与 dirty 状态、组件/模型/依赖哈希、机器与规则版本、完整命令、输入/日志、时间账本、失败原因、必要整场视频及哈希；评测真值单独权限保存，不能回流算法。记录通过/失败/阻塞及独立复核人；未经实际执行不填通过。跨场景、平台、算法或规则版本不能沿用旧通过结论。

T01/T13 新增 `state_projection.py` 与 local `AdmissionPolicy`：operator state 只发 scope 内静态 roster、公开比赛字段、有效本会话 lease 车本车 HUD与自己控制；frame 只发实际 JPEG/静态 K/D/外参/原时钟，删除 capture own pose/odom。role/scope 来自 server-owned grant，HTTP 默认 fail closed；spectator truth 需要显式 audit。104 项权限/HTTP/SDK/control/camera 检查通过；62 项 offline/admission/camera/projection 检查通过，终态与 renewal/cleanup 不需开放离线真值。实际 local grant QA 已跑 multiclient 20、GL camera 35、resupply 15 checks，均通过。详见 [ADMISSION.md](ADMISSION.md)。局部证据不关闭 A10；两电脑 LAN、远程权限/身份、恶意插件沙箱与真实点云定位仍未验收。

固定 Qt `0cedf99` 的旧 v2 parser 依赖全车真值字段，必须显式应用兼容补丁，禁止伪造 xy/HUD。patched-client 的可见 GUI、选择→claim→arm 交互与整场运行还需实测，不能以 parser CPU 检查代替 A01/A04/A07/A10。
