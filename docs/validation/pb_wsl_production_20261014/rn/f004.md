## Concrete production issues and minimal fixes

1. **Production status reports zero odometry even after actual LIO.** Worker
   lines 261–263 select `odometry_messages=0` and `errors=[]` whenever observer is
   absent. This is the normal production mode. Gate map count is real, but actual
   odometry and activation errors are not represented. Count real callbacks on
   the existing bridge odometry subscription, expose the actual last stamp as a
   diagnostic scalar, and return the gate's own activation state/errors. Do not
   synthesize counts from scan sequence or infer a successful estimate from map.

2. **Concurrent status calls terminate the control session.** Session exchange
   lines 300–303 reject a busy transaction and call `request_stop`, including
   `status()`. A monitor polling this API while a 50 ms act is outstanding can stop
   all nine algorithm groups. There is currently no HTTP status route using it,
   so this is an API integration risk, not a demonstrated HTTP-control bypass.
   Keep the existing act concurrency guard. Provide a detached cached status
   report or a separate bounded monitor channel; alternatively explicitly define
   status-busy as a non-mutating error after parent review. Do not queue an
   unbounded monitor behind control or change the original act deadline.

3. **Activation and shutdown can race on lifecycle resources.** Production gate
   starts a thread calling Stack.activate_navigation; worker finally calls
   Stack.stop *before* Gate.close joins that thread. Activation may then execute
   `_lifecycle`'s `finally: self.node.destroy_client` against a destroyed node.
   Concurrent activation error also calls Stack.stop; Stack.stop's second caller
   can wait up to 5 seconds, inconsistent with host close's 1.3-second envelope.
   Signal cancellation first; separate group termination from lifecycle node
   teardown; join/cancel the activation operation using the same shared cleanup
   deadline before destroying its executor/context. Preserve failure if a
   callback cannot exit. Add an activation-wait→stop fixture that proves both
   thread and groups reaped, not just normal idle shutdown.

4. **Production diagnostics do not persist the host ledger.** Worker saves Linux
   phases when enabled, but Session.close and the ordinary CLI do not write
   `phase_rows`; only the test-goal QA harness does. The 4096-row cap also silently
   stops host logging after roughly 682 full transactions (~68 seconds at 10 Hz),
   shorter than the CLI default 300 seconds. Preserve bounded diagnostics with a
   dropped-row count and explicit completeness flag; persist a snapshot after
   authority stops without including raw cloud bytes or extending control time.

5. **Failed prepare cleanup is deliberately conservative but hard to diagnose.**
   `_check_cleanup` requires `ready` process identity, so even a correctly reaped
   pre-ready worker cannot be accepted when preparation timed out. The worker
   already writes `WORKER_STARTED.json` (PID/start_ticks/boot), but it lacks
   run/config/spec identity. Distinguish never-ready qualification failure from
   resource cleanup; if parent adopts a startup identity record, bind it to the
   run/config/spec and require exact source guards. Never turn this fallback into
   preparation success or authorization to process an old observation.

6. **Registry prepare failure suppresses secondary cleanup failure.** Registry
   lines 68–72 swallow `session.close` exceptions and rethrow prepare's exception.
   The current CLI mitigates this with an early capturing `session_factory` and
   a second final close, but direct callers cannot assume cleanup succeeded.
   Return/store both failure causes or chain a cleanup error with the original
   preparation exception; the original cause must remain reviewable.

## Gate behavior that is not a detected defect

`lookup_transform(map, base_link, Time())` is only a one-time presence prerequisite
for activating the original planner/controller. It is not converted to velocity
or stamped as a fresh scan. The actual controller path retains original request
context and exact actual-localization pose stamp, and Host still rechecks leases,
episode, epoch, activation, original wall and simulation budgets. A fresh unique
namespace/single generation prevents reuse of prior generation's scoped map.
Missing TF keeps navigation inactive. No identity fallback or ideal pose feed was
found in this path. Whether its ROS initialization/QoS actually works in production
must be measured, not inferred from AlgorithmObserver runs.
